# TJ-Sync

配合 [TJ-VideoPrep](https://github.com/xunmeiruxue/TJ-VideoPrep)（分离 / 转码）与
渡幕 Trans-Jimaku Web（打轴）使用的配套工具。

职责划分很清楚：TJ-VideoPrep 管"打轴之前"——把电影分离成音频和预览视频；
本仓库管"打轴进行中"和"对齐是否可信"。

**两者都不改动打轴软件的任何文件。**

| 组件 | 用途 |
|---|---|
| `userscript/tjw-video-panel.user.js` | 打轴时在旁边显示画面，跟随打轴软件的播放头 |
| `tools/make_calib.py` | 生成校准片，检验整条链路有没有时间偏移 |

---

## 一、画面面板

### 它做什么

打轴时你操作的是渡幕，播放头、波形都在它那边。这个面板在渡幕界面里旁挂一块画面显示，
把 TJ-VideoPrep 生成的 `preview.mp4` 放出来，**跟着渡幕的播放头走**。

渡幕的音频、波形、播放头、字幕操作全都不受影响——脚本只读它的播放位置，不碰它的音频，
所以你听到的声音仍然是渡幕放的，这边只出图像。

### 安装

1. 浏览器安装 Tampermonkey
2. 新建脚本，把 `userscript/tjw-video-panel.user.js` 的内容整个粘贴进去，保存
3. 打开渡幕，面板会出现在右上角

### 使用

1. 用 TJ-VideoPrep 分离时勾上「视频 · 预览版」，得到 `xxx.preview.720p.mp4`
2. 在渡幕里打开项目并开始播放
3. 面板上点「选视频」选中那个 mp4（也可以直接把文件拖进面板）
4. 画面自动跟随；标题栏实时显示漂移量与当前位置

面板可拖动、可缩放，「—」按钮收起。标题栏的「偏移」是 ±ms 微调，正常情况下保持 0。

### 实现要点

- **必须 `@run-at document-start` 且 `@grant none`**。脚本要运行在页面世界才能 hook 到
  渡幕的播放器——那是一个 `new Audio()` 全局单例。一旦使用任何 `GM_*` API，
  Tampermonkey 会把脚本放进沙箱世界，就 hook 不到页面对象了
- 播放时让 video 自然播放，只在漂移超过 80 ms 时做一次校正；暂停时精确对齐。
  每帧强行 seek 会把解码拖死
- 视频文件经 File System Access API 选择，句柄存进 IndexedDB，下次打开自动恢复
  （需要点一次授权）

## 二、校准片与闭环校验

### 为什么需要

TJ-VideoPrep 会报一句"音轨比视频晚 14 ms，导出音频时将在头部补静音对齐"。
这个补偿是推导出来的，**必须实测确认它真的成立**——如果它其实偏了，
你打的轴会整体偏移，而这种偏差往往在打了几个小时轴之后才暴露。

### 生成

需要 Python 与 ffmpeg：

```
python tools/make_calib.py H:\TJ-Sync\calib
```

产出 `calib-30s.mkv` 与 `calib-30s.mp4`，设计目标是**不用听声音就能判断位置**：

- 音频除脉冲外是**严格的数字静音**，所以波形是一条平线
- 每 5 秒一个脉冲，宽 5 毫秒、幅度 95%，在波形上就是一根满幅竖线
- 画面在每 5 秒闪一帧纯白，与音频脉冲同一时刻；另有随时间横向移动的方块

### 判据

把校准片当作普通视频走一遍完整流程：

```
校准片 → TJ-VideoPrep 分析 → 分离音频 → 导入渡幕 → 看波形
```

波形上的竖线必须**精确落在 5 / 10 / 15 / 20 / 25 秒**。
偏了就说明链路存在系统性偏移，偏差量可以直接量出来。

### 已实测的特性

| 项目 | 实测值 |
|---|---|
| 视频流 start_time | 0.000000 |
| 音频流 start_time | 0.000000 |
| 脉冲位置 | 5.0000 / 10.0000 / 15.0000 / 20.0000 / 25.0000 秒 |
| 脉冲之外的峰值 | 0（严格静音） |
| 画面闪帧位置 | 0 / 5 / 10 / 15 / 20 / 25 秒 |

两条流的起点一致，所以判据干净：竖线必须落在整秒上。

换了 ffmpeg 版本、改了分离参数、或遇到新的容器类型时，重跑一次即可。
